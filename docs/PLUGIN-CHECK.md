# WordPress.org submission check

Plugin Check 2.1.0 was run against the **installed 0.1.1 ZIP**, with static and runtime checks enabled, in a disposable WordPress 7.1.3/PHP 8.3 site. It reported **zero errors and 58 warnings**. The findings below were reviewed against the code and are deliberate uses of the relevant APIs rather than unresolved security defects. The check does not replace a manual security review or a real sign-in with the selected identity provider.

| Finding | Count | Disposition |
| --- | ---: | --- |
| `WordPress.Security.NonceVerification.Recommended` | 15 | The public metadata document and JWKS are read-only GET/HEAD routes. An ordinary login start cannot require a WordPress nonce before authentication. Its callback consumes a one-time, ten-minute OAuth state and verifies PKCE, issuer, nonce and a signed ID token. The administrator test-login start separately requires a WordPress nonce and `manage_options`; the settings POST uses `check_admin_referer` and `manage_options`. |
| `WordPress.DB.DirectDatabaseQuery.DirectQuery` | 11 | The plugin uses MySQL advisory locks and an atomic transaction delete to make callbacks single-use across concurrent processes and object caches. It queries user email rows directly to detect duplicates, which WordPress does not forbid at the database level. Installation checks its custom table; explicit uninstall removes that table and retained options. All variable values and identifiers in these queries are prepared. |
| `WordPress.DB.DirectDatabaseQuery.NoCaching` | 10 | Caching locks, one-time transactions, duplicate-email lookup or uninstall state would invalidate the concurrency and deletion guarantees. These reads intentionally hit the database. |
| `WordPress.Security.ValidatedSanitizedInput.InputNotSanitized` | 9 | The error reference is unslashed, accepted only as 12 lowercase hexadecimal characters, and HTML-escaped. Request method is compared with fixed values. The remote address and User-Agent are hashed, never rendered or stored raw. The bounded raw query string is used only to reject duplicate callback keys. OAuth parameters are unslashed, bounded and checked by protocol-specific validators before use. |
| `WordPress.Security.ValidatedSanitizedInput.MissingUnslash` | 8 | These are `$_SERVER` values. WordPress slashes `$_GET` and `$_POST`, which the plugin unslashes at request boundaries; it does not slash the web server's method, address, User-Agent or raw query string. Unslashing the raw query string would change what the duplicate-key check is examining. |
| `WordPress.NamingConventions.PrefixAllGlobals.NonPrefixedHooknameFound` | 2 | `wp_login` is a WordPress core action that integrations expect after a successful login. `oauth_cimd_auth_http` is the previous plugin's compatibility filter, retained for existing integrations. The plugin's new filter is prefixed `soca_http`. |
| `WordPress.DB.DirectDatabaseQuery.SchemaChange` | 2 | These are the two custom-table drops in `uninstall.php`, executed only when the site owner explicitly defines `SOCA_ERASE_DATA` (or its legacy equivalent) before uninstalling. Deactivation and ordinary uninstall retain data for recovery. |
| `WordPress.Security.SafeRedirect.wp_redirect_wp_redirect` | 1 | OIDC requires navigation to the configured provider's external authorization endpoint. Discovery is fetched over pinned HTTPS, its issuer is matched exactly, and its endpoint is validated as a public HTTPS URL before `wp_redirect` is called. `wp_safe_redirect` would reject that intended external host. |

The installable ZIP includes `composer.json` alongside its bundled JWT library, so the development-mount `missing_composer_json_file` warning is absent. It contains no tests, build tools, logs or evidence files. The source repository links from `readme.txt` and contains the detailed docs and build process. The installable ZIP is below WordPress.org's 10 MB limit.

The 0.1.1 protocol suite (28 groups) and disposable WordPress integration suite (20 groups) pass. The WordPress run used `WP_DEBUG=true` and produced no notices or warnings. A live end-user login through the default RESOAuth hosted gateway remains unverified.
