# 0.1.0 directory release notes

The installable archive is `dist/simple-oauth-cimd-access-0.1.0.zip`; `dist/simple-oauth-cimd-access-0.1.0-source.zip` contains the repository tooling and tests. Generate both with `python3 tools/build.py`, then verify `dist/SHA256SUMS`. The installable ZIP has one top-level `simple-oauth-cimd-access/` directory and includes `readme.txt`, the main plugin file, runtime source, `composer.json`, licenses, and documentation.

The plugin header and directory readme both use version/stable tag `0.1.0`, WordPress 6.8, PHP 8.1, and the `simple-oauth-cimd-access` text domain. The display name is **Simple OAuth CIMD Access**, so the expected directory slug matches the plugin folder. `Author: RESOAuth` and its GitHub organization URL are in the plugin header; the plugin URI points to this repository. The Composer package is `resoauth/simple-oauth-cimd-access`.

For an initial WordPress.org submission, upload the installable ZIP through the [plugin submission page](https://wordpress.org/plugins/developers/add/). WordPress.org assigns the directory slug during review. After approval, copy the installable folder's **contents** into the assigned SVN repository's `/trunk/` (the main PHP file must sit directly in trunk), copy trunk to `/tags/0.1.0/` with `svn cp`, and commit trunk and tag together. Confirm `Stable tag: 0.1.0` in both readmes. Follow the [WordPress.org SVN instructions](https://developer.wordpress.org/plugins/wordpress-org/how-to-use-subversion/).

The WordPress.org `Contributors` field is intentionally omitted until the submitting team supplies a verified WordPress.org username. The PHP `Author` field already identifies RESOAuth. The directory listing links to the [default hosted gateway documentation](https://sag.resoauth.dev/hosted), its [privacy notice](https://sag.resoauth.dev/hosted/privacy-notice) and [terms of service](https://sag.resoauth.dev/hosted/terms-of-service). The separate [RESOAuth Dynamic CIMD](https://dynamic-cimd.resoauth.cloud/) service is linked and disclosed as the default metadata proxy for local development. Previously saved proxy settings are not rewritten during upgrade; operators must change the template themselves if they wish to move an existing client ID.

Plugin Check 2.1.0 reported zero errors and 70 warnings against the mounted development plugin. The WordPress HTTP API sends outbound requests; its `http_api_curl` hook pins the resolved public address while checking the TLS hostname and certificate, preventing a DNS change between validation and connection. The packaged plugin includes `composer.json`, addressing one of those warnings. Remaining warnings about public callback nonce checks, atomic database queries, and input handling require manual context review. See [security decisions](SECURITY.md) and [test evidence](TESTING.md); do not treat the static scan as a security audit.
